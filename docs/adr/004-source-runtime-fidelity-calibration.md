# ADR-004：使用源项目实机采集校准组件预览保真度

## 背景

静态源码分析可以恢复组件导入、字面量 props、局部样式和部分 Provider，但无法证明浏览器中的最终布局、字体、主题、伪类状态和运行时生成结构。继续增加组件名 fallback 或猜测业务数据只会让预览“看起来能运行”，不能证明它贴近源项目。

下一阶段要求资产工作台中的组件预览尽量贴近源代码实际运行效果，同时保持本地优先、低占用、增量执行和不伪造业务状态。

## 决策

采用显式双通道：

1. 静态快速通道始终可用，只读取源码并生成可证明的场景和运行上下文。
2. 实机校准通道仅在用户允许时启动或连接源前端，以公开、无需登录的真实页面作为视觉与结构基准。
3. 实机采集采用项目级短生命周期会话：一个源服务、一个浏览器实例、串行批量采集；完成后关闭并检查子进程。
4. 采集输入、基准产物、候选产物和比较报告使用完整 SHA-256 与现有 SQLite/CAS 协议持久化；未变化输入不得重新启动源项目。
5. 保真度分为运行、几何、视觉和结构四层。运行、几何和结构是第一阶段硬门槛，视觉像素差异是带容差的趋势指标。
6. 定位证据不足、多实例歧义、鉴权、业务后端或路由不可达必须显式记录，不得随意选择元素或生成假数据。
7. 实机通道不修改源项目文件，不向 DOM 注入影响布局的 wrapper，不执行业务写操作，不自动登录。

## 备选方案

### 仅静态重建

- 优点：启动快、占用低、完全确定性。
- 缺点：无法观测最终浏览器结果，保真度存在不可突破的上限。
- 结论：保留为快速通道，不作为高保真证明。

### 每个组件独立启动源项目

- 优点：隔离清晰。
- 缺点：冷启动、依赖预构建和浏览器启动被重复支付，资源与时间不可接受。
- 结论：拒绝。

### 长驻源服务与浏览器

- 优点：连续采集最快。
- 缺点：默认长期占用内存，容易遗留进程，运行环境会随时间漂移。
- 结论：不作为默认模式；未来可作为显式开发模式另行设计。

## 信任边界

- 启动源项目会执行其 package scripts，属于执行用户指定本地代码，必须由用户显式启用。
- 第一阶段只访问 loopback（本机回环）地址和公开路由。
- 不收集环境变量值、Cookie、Token、请求体或业务响应正文。
- 采集报告不得包含绝对路径和秘密；调试日志只保存必要错误摘要。
- 遇到登录页、权限跳转或外部站点时停止该路由采集。

## 后果

- 未变化项目继续走静态或缓存命中路径，不产生源服务和浏览器开销。
- 首次实机校准成本受源项目自身冷启动影响，不能承诺固定耗时。
- 需要新增浏览器自动化依赖、采集协议、进程监管、组件定位、图像比较与工作台诊断界面。
- 高保真成为可验证状态，而不是一个由启发式代码自我声明的布尔值。

## 第一阶段范围

- React、Vue、uni-app H5。
- 无需登录、可直接访问的真实页面。
- 默认、hover、focus 和可安全执行的本地交互状态。
- 不覆盖登录后页面，不连接真实业务后端，不自动制造业务数据。
