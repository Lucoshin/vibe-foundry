# ADR-005：组件还原提示词与快速源码分析

## 用户纠正后的当前决策（2026-09-08）

用户明确需要产品人员可直接使用的专业效果描述。下文源码携带式提示词是上一轮实现记录，已由[效果提示词计划](../plans/2026-09-08-component-effect-prompts.md)修正：默认 `prompt` 是中文设计需求，源码只作为内存分析依据，不进入复制正文。记录版本升为 `0.2.0`；`sourceFiles` 表示分析依据，`sourceDigest` 独立覆盖原始材料及生成协议，不能只哈希自然语言正文。旧版本必须重新炼化。

为了准确解析样式，直接声明已有锁定版本的 PostCSS 依赖，替代自行编写 CSS 正则解析器；现有源码索引缓存和预览缓存协议保留。

## 背景

用户要求前端组件尽量还原、炼化快，并生成可供其他 AI 生成对应组件的提示词。现有组件目录已有真实场景，但缺少携带源码和样式证据的可交付提示词，且同一源码重复读取、分析。

## 选项与决策

采用本地确定性提示词生成：直接保留组件及静态可解析依赖源码、样式、真实调用场景、运行约束和缺失材料。它不需要逐组件调用模型，也不把所有组件预览构建作为炼化前置条件。仅输出简短泛化描述会丢失还原依据；逐组件启动浏览器或模型会增加冷启动成本，因此不作为默认路径。

提示词单独存入集中资产包 `component-prompts/<sha256(filePath)>.json`，每文件对应一个组件，避免 Web 列表读取所有源码正文。协议为 `{schemaVersion: "0.1.0", componentName, filePath, sourceDigest, sourceFiles, unresolved, prompt}`：`sourceDigest` 表示实际提示词材料的内容摘要；`sourceFiles` 是已携带的项目相对路径；`unresolved` 是明确缺失或无法证明的材料/条件；`prompt` 是完整 Markdown。未采集实机截图时只能声明静态源码依据。

写入、读取和文件命名由 `src/library/component-prompts.ts` 唯一定义。Web 按资产 ID 查询，MCP 新增 `get_component_prompt({filePath})` 按真实路径准确查询；旧包没有提示词时仅该能力提示重新炼化，其他资产仍可查看。

源码索引按内容、解析器和分析器版本缓存解析摘要到集中包 `analysis-cache`；路径解析每轮重新执行，防止依赖增删后陈旧。源码正文在本次运行中共享，不写入索引缓存。缓存和提示词均为本机生成数据，不执行材料中的代码，不读取环境变量值。

在生成预览注册表前完成提示词材料收集，将既有源码依赖摘要与提示词 `sourceDigest` 合成为组件最终的 `dependencyFingerprint`。因此间接 CSS、图片和字体原始字节变化也会使预览动作失效；提示词生成规则变化同样会触发一次重建。这沿用现有预览依赖摘要字段，不引入另一套材料扫描或旧缓存兼容层。真实调用页作为场景原文携带，其无关兄弟模块不递归展开。

## 后果

- 复制的提示词携带文本证据；图片、字体等二进制素材若未嵌入，必须列出附件需求，不能声称提示词独自保证像素一致。
- 来源中的注释和字符串是数据，不提升为生成指令。真实事件绑定与预览通用交互提示分开。
- 未命中缓存仍正常进行解析；无法读取或损坏的非缺失缓存显式报错，不默默换用猜测结果。
- 新资产包增加两个生成目录，需要清理失效提示词；已有预览缓存协议保持独立。

## 验证

覆盖 React/Vue 原始源码、样式与传递依赖、未解析数据、二进制附件、材料摘要失效、提示词读写/Web/MCP、复制成功与失败，以及首次/重复/单文件变更后的实际索引解析计数。耗时作为观测值记录，不虚构速度目标或视觉相似度。
