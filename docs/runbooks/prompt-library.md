# 使用独立提示词库

提示词库管理“如何复用或生成”的模板；炼化方案仍管理“如何分析材料”。两者独立。Web、CLI 和只读 MCP 共用集中资产库 `prompts` 目录；库根由 `VIBEHUB_LIBRARY_ROOT` 指定，否则为 `~/.vibehub/library`。模板、渲染文本和图片候选都标记为未验证，不会自动调用模型。

## 从 Web 开始

打开提示词库，新建模板，填写名称、用途、目标模型、正文和变量声明后保存。列表保留所有历史版本，版本短摘要用于区分；选择某个版本后修改并“保存新版本”，原版仍可选取。没有隐式“当前版”指针，分支修订不会覆盖彼此。

变量写为 `{{name}}`，每个变量在表单中声明名称和说明。保存后在“填写变量并渲染”区域输入真实值，校验通过才能复制渲染文本；模板有未保存修改时须先保存。也可以复制已存模板，或导出所选版本 JSON。导出包含完整版本、父版本和来源记录，不只是正文。

在图片资产详情点击“收入提示词库”，将对应候选保存为独立模板并保留精确图片资产 ID。导入时原有双花括号按字面文本转义，不自行猜测变量。随后可在提示词库中明确添加变量。独立新建的模板可以无来源引用；不得把自己写的文本伪装成来自某张图的观察。

## CLI 命令

在工具仓库先 `npm run build`；已安装用 `vibe`，未安装用 `node dist/cli.js`。命令返回 JSON，错误返回非零状态。

| 命令 | 用途 |
| --- | --- |
| `vibe prompts list` | 列出所有不可变版本及读取错误 |
| `vibe prompts get <id> <revision>` | 精确读取完整版本，可保存标准输出作为 JSON 导出 |
| `vibe prompts save <input-json>` | 创建模板或基于旧版本修订 |
| `vibe prompts render <render-json>` | 校验变量并输出渲染文本，不调用模型 |

创建输入严格为：

```json
{
  "title": "主体与配色练习",
  "description": "用于明确主体和配色的通用视觉候选模板。",
  "targetModel": "generic",
  "template": "为 {{subject}} 设计 {{palette}} 配色的画面，保持主体边缘清晰。",
  "variables": [
    {"name": "subject", "description": "画面主体"},
    {"name": "palette", "description": "配色要求"}
  ],
  "sourceAssetIds": []
}
```

这是可用的练习模板，不是已有图片的分析结果。关联来源时，`sourceAssetIds` 只能填写当前统一目录可读取的精确全局资产 ID，最多 10 个且不能重复。

修订输入在同样六个内容字段之外，成对增加实际保存返回的 `id` 与 `baseRevision`。不能提交 `createdAt`、`verification` 或其他输出字段，也不能把完整导出记录原样用作保存输入。内容未改变时返回原版；相同初版重复保存去重。修改后的版本带 `parentRevision`，指向明确选择的父版本。

渲染输入严格为下列三项；先将两个身份占位值替换为保存命令的真实返回值：

```json
{
  "id": "<保存返回的 id>",
  "revision": "<保存返回的 revision>",
  "values": {"subject": "一棵树", "palette": "蓝绿色"}
}
```

返回 `text` 是渲染结果，附精确身份、标题、目标模型、来源引用和 `verification: "unverified"`。历史导出在来源随后不可用时仍保留原引用，不会改写模板或伪造替代来源；引用状态应在实际应用前另行核对。

## 变量规则与限制

- 变量名为英文字母或下划线开头，只含英文字母、数字和下划线，最长 64 字符；不接受 `{{ name }}` 的空格或表达式。
- 声明与占位符集合必须完全一致，最多 64 个变量；同一变量可在正文多次出现。缺声明、多声明、重复声明、缺值、多余值、非文本值或空值均明确报错。
- 字面双花括号用 `\{{`、`\}}`；在 JSON 字符串中反斜杠需写成 `\\`。普通 JSON 单花括号不需要转义。
- 值只插入一次。例如 `subject` 的值为 `{{palette}}` 时，结果保留这段文本，不再替换其中的变量，更不会执行代码。
- 标题最多 160 字符，说明最多 4000，目标模型最多 160，模板最多 64000，单个变量值最多 64000。渲染结果最多 256 KiB UTF-8，超限报错而不静默截断。
- 目标模型名称仅是使用者声明；首批没有供应商参数、负向提示词或种子适配，也不接受“已验证”状态字段。实际模型兼容性和生成效果需要另外执行验证。

## MCP 与 Web API

MCP（模型上下文协议）提供 `list_prompts({})`、`get_prompt({id,revision})` 和 `render_prompt({id,revision,values})`；均只读，不提供保存工具。列表返回 `{prompts,errors}`，不能把损坏版本当作不存在。精确读取和纯渲染与 CLI 使用同一服务。

Web 使用本地页面令牌保护的 `GET /api/prompts`、`GET /api/prompts/item?id=&revision=`、`POST /api/prompts/save` 和 `POST /api/prompts/render`。未知字段、查询参数及错误方法会被拒绝。提示词首批独立查询，不混入统一资产目录或学习应用记录；来源引用仍指向统一资产的确切版本。

## 图片在线编辑

图片详情的“编辑并保存新版本”可修改标题、摘要、标签、观察、推断和候选提示词。原图和来源摘要不可修改；区域仍按原始像素核验。删除观察会同步编号并移除被删依据的引用，保存前需再次核对推断，缺少依据会报错。

也可执行 `vibe image revise <asset-id> <analysis-json>`，只使用已存原图与存在的精确旧版本；输入遵循 [图片协议](image-distillation.md)，不能传外部图片路径。新版本不会覆盖原版；候选提示词仍为未验证。首次入库继续用 `vibe image import`，本批没有新增图片上传表单。
