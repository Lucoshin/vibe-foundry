# 零点零工真实项目炼化验证

## 目标与范围

- 导入零点零工移动端和管理后台，产物只写集中资产库，不修改源项目。
- 管理后台首次导入成功；移动端在组件效果结构分析中遇到 uni-app 条件编译的重复声明，阻断整次导入。
- 已复现：同一方法的 `APP-PLUS` 与非 `APP-PLUS` 分支分别声明 `initDelay`；基础索引和资源分析已使用 Babel 可恢复解析，效果结构分析仍为严格解析。

## 最小修复

- 修改 `src/analyzers/component-design-structure.ts`：Vue 脚本沿用可恢复解析；存在解析错误时明确记录未确定项，清空所有脚本绑定，只提取独立可确认的模板结构。
- 不选择平台、不虚构属性值；不可恢复的语法错误仍显式失败，不新增编译器、平台兼容层或兜底源数据。
- 新增结构单测与炼化集成回归：复现互斥分支重复声明，确认导入产物存在且不把不确定绑定写成真实文案。

## 验证

- 先运行新增测试，确认旧实现失败；实现后运行相关测试、`npm test`、`npm run build`、`git diff --check`。
- 通过 Web 导入 API 重新导入移动端，读取两端报告、资产数量，浏览器核对组件详情及实际预览状态。
- Vue 2 管理后台运行预览、Java 后端提取不在此次修复范围内。

## 结果

- 已完成最小修复；新增两项测试在修复前均复现重复声明错误，修复后结构与炼化相关 29 项测试通过。
- 通过运行中的 Web 导入 API 导入管理端约 3.1 秒；移动端修复后重试约 4.1 秒（复用了首次扫描缓存，不能当作完整冷启动耗时）。
- 移动端产物记录 100 个组件、49 个服务候选、5 个业务模式、268 个设计令牌、320 个页面模式、8 个概念资产；管理端 34 个组件，其余类型为 0。数量来自生成清单，规则识别结果仍需复用前审核，服务候选包括测试文件命中。
- 浏览器已实际显示移动端 AppEmptyState 的“暂无数据”；这不代表全部 100 个组件或平台运行行为已通过验证。
- 本次删除 Vue 结构分析与现有索引的严格解析差异；保留不可恢复错误显式失败、原始素材、现有缓存和源码只读契约。未新增平台预处理或修改零点零工代码。
- 用户随后补充预览黑底错误及布局抖动问题，已完成，见[预览错误状态](2026-09-15-preview-error-states.md)与[预览提速计划](2026-09-15-preview-reliability-and-speed.md)。

## 真实插槽内容修复

- 实际打开移动端 `ld-button` 嵌入预览时，运行时把没有调用场景的默认插槽填成了虚构候选人、岗位和更新时间；这些内容不属于源组件。
- Vue 预览只注入 `previewScenario.slots.default` 中已确认的真实调用文本；没有真实插槽内容时不传插槽，保留源组件默认内容。
- 删除用于合成演示插槽的源码扫描、失效参数、模板生成函数及配套 CSS，不扩大具名插槽分析范围。
- 回归验证：无场景时不出现虚构业务文案、不覆盖源插槽默认值，真实默认插槽文本仍按来源传入；运行预览相关测试与构建检查。
- 验证结果：新增无场景断言在旧实现上复现虚构插槽；修复后 `npm run build` 和预览运行时 42 项测试通过，真实默认插槽传入的既有回归持续通过。
