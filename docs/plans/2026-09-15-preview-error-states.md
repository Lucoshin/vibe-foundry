# 组件预览不支持状态与稳定等待界面

> 后续变更：本文 Vue 2 一律拦截为历史措施，已由 [双版本预览](2026-09-15-vue-dual-preview.md) 取代。中文错误页和稳定等待机制继续有效。

## 已确认问题

- 零点管理后台 `ruoyi-ui` 使用已安装的 Vue 2.6.12；现有 Vue 预览生成器使用 Vue 3 `createApp`，两者不兼容。
- 组件仍被标记为可构建，自动预览不断尝试无意义构建；已有 `BUILD_ERROR` 缓存掩盖了明确原因。
- 预览错误直接返回纯文本，浏览器深色模式会呈现黑底内部报错；等待页每 0.8 秒整页刷新，造成闪烁。

## 最小修复

1. 使用源项目实际安装的 Vue 主版本做兼容性预检；Vue 2 返回明确的不支持状态，不替换框架版本，不伪造预览。
2. 资产视图在缓存状态之前投影兼容性问题；服务端在读取失败缓存及排队构建之前做同一检查。现有 CLI 构建依赖预检复用该判断。
3. 预览失败保留 HTTP 500，并返回固定浅色、简洁中文 HTML。技术错误折叠显示且转义，不再把原始报错作为页面正文。
4. 等待页仅通过后台请求探测状态，等待期间不重建 iframe 页面；成功后只导航一次。探测返回失败时直接展示该次请求的错误 HTML，避免再次导航触发重试；失败页不轮询、不自动刷新。

## 验证

- Vue 2 拦截、Vue 3 不误拦截、既有负缓存被兼容性原因覆盖。
- 不支持的组件不执行构建；错误 HTML 保留失败状态且不循环；后台状态探测不刷新等待页面。
- 定向测试、构建和差异检查。真实管理后台只读验证，不修改源项目或重启正在运行的服务。

## 结果

- 已实现源项目已安装 Vue 主版本预检：同次资产视图按运行时只检查一次，不持久缓存版本；Vue 2 兼容性问题优先于旧构建失败缓存。
- 已清理旧 `loadingPreviewHtml` 和周期整页刷新；等待与错误使用同一浅色状态模板。HTTP 500、动作缓存、版本归属和挂载验证契约保持不变，原始技术错误仅在折叠区转义显示。
- `npm run build` 通过；依赖预检、资产视图及 Web 服务定向测试 43 项通过，差异检查通过。
- 对真实 `ruoyi-ui` 的 Breadcrumb 做不启动服务的只读请求验证：返回 HTTP 500 / `text/html`，正文明确 Vue 2 / Vue 3 边界，没有旧 `Cached component preview` 文案，构建调用次数为 0。
- 本次未修改源项目、未替换 Vue 版本、未重启 4317；真实浏览器统一验收由主任务执行。

## 统一验收（2026-09-15）

- `npm test`：405 项通过，57 个测试组，零失败；包含构建。`git diff --check` 通过。
- 已重启 4317 Web，刷新示例工程及零点两端产物；最终移动端导入约 10.9 秒、后台约 1.7 秒（现有缓存与本机负载条件下）。
- 在线 API 确认零点两端共 134 个组件；Breadcrumb 为 blocked，返回中文 HTML 与 HTTP 500，不执行无意义构建，也无自动刷新。
- 浏览器截图确认管理后台卡片固定占位、详情显示 Vue 2 支持边界，无黑底内部报错。
