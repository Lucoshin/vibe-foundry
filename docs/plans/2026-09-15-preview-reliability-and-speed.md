# 组件预览修复与首次展示提速

## 目标

修复示例组件的 BUILD_ERROR，避免失败后无限刷新；启动 Web 或导入项目后尽早看到可运行的组件预览。保留真实源码、依赖和缓存完整性，不生成假预览。

## 已确认问题

- 首次点击才执行 npx 构建，工具准备延迟与源码构建混在一起。
- 预览失败后入口仍返回自动刷新的加载页。
- 每个预览资源重复加载全库视图，并重复校验整棵缓存产物树。
- 示例工程没有安装运行依赖，需用真实依赖验证，不能把源码分析 fixture 当作已可运行项目。
- 实际配置将 esbuild 限制为 .js/.jsx，排除了 .tsx，导致合法 JSX 源码在导入分析时失败。

## 实施范围

1. 在 `src/preview/component-preview-runtime.ts` 定位并修复真实构建问题；将已选定版本的 Vite/Vue 构建工具固定为本地依赖，用 Node 直接启动，删除 npx/shell 分支。
2. `src/web/server.ts` 明确失败响应；资产页面与导入完成后有限后台预热，共享已有动作缓存与构建去重。预热不阻塞资产读取、不等待全部组件。
3. 前端提供真实组件缩略预览或明确的构建状态，详情/大预览保持按需开启；只加载有限可见组件，避免大量 iframe 同时启动。
4. 示例使用真实 React 运行依赖，重新炼化并验证缓存命中。必要配置修复遵循源头，不伪造 Provider、样式或数据。
5. 清理重复工作与失效调用；不扩展书籍解析或更改已有资产语义。
6. 搜索按资产 ID 保留未变卡片和缩略预览节点；固定预览资源的动作版本，避免重炼期间旧 HTML 请求新版本产物而失败。

## 验证

- 先补失败回归，再实现；覆盖构建路径、本地工具、跨盘源码、失败不循环、预热与点击去重及真实缓存复用。
- `npm test`、`npm run build`、`git diff --check`。
- 记录示例解析、首次构建、缓存读取耗时；浏览器检查真实按钮渲染、首次列表预览及导入后刷新。
