# Web 克制简约交互实施计划

**Goal:** 按用户确认的截图评估，统一视觉语言并稳定浏览、详情、预览和导入流程。

**Architecture:** 保留原生 Web 和现有资产契约；将重复覆盖的样式收拢为单一 `web-styles.ts`，视图按职责局部更新，导入选择与任务阶段分开。

**Tech Stack:** Node.js、原生 HTML/CSS/JavaScript、Node 测试。

## 1. 真实数据和状态

- `asset-view-model.ts` 依据实际可读资产计算集中库分类统计，与总数一致；聚合模式不显示未知生成时间。
- 导入面板区分选择、运行、结果阶段，历史任务只在任务视图展示。
- 先补统计/状态回归测试，复现失败后实现。

## 2. 稳定交互

- 默认不选中首项、不占右侧详情；点击条目打开可关闭的详情面板。
- 显式预览按钮打开独立工作区，返回时保留列表与滚动位置；鼠标悬停不创建 iframe。
- 搜索只更新列表；导航不反复销毁重建；同一预览不因搜索重新挂载。
- 组件使用卡片，设计令牌、服务等使用紧凑行；普通详情折叠原始 JSON。

## 3. 统一样式

- 暖白/中性灰底色、清晰无衬线排版；统一边框、6px 圆角、8/16/24/32 间距，120–180ms 轻反馈。
- 删除手稿粒子、倾斜卡片、编号、field note、虚拟百分比评分、悬浮预览及对应失效状态和测试断言。
- 统计为轻量摘要，动作只保留必要主次；标签避免语言重复。

## 4. 验证与交付

- Node 定向测试：统计、详情选择/关闭、预览复用、返回列表、搜索不重建详情、导入阶段、原提示词事件回归。
- `npm test`、`npm run build`、`git diff --check`。
- 浏览器截图与交互：总览、列表、详情、预览返回、导入各阶段、窄屏与键盘操作。
- 更新使用手册和实施记录；保留真实业务结果、已有 CLI/MCP 和集中库边界。
