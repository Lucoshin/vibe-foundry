# 将组件效果翻译成专业设计描述

## 用户纠正与验收目标

用户需要帮助产品人员把“看到某个组件，想要这种效果，但不会用专业术语描述”转化为可交给其他 AI 的设计需求。上一轮携带源码的还原指令偏离了这个目标。默认输出改为中文效果描述，覆盖有依据的布局、视觉层次、配色、材质、动效和交互；不让用户拿着源码与工程元数据再去翻译。

用户已选择默认按“布局、视觉、动效、交互”详细分项，真实确认的尺寸和动效参数可以保留。现阶段从真实源码结构和样式声明提取依据；不把没有实机观测的效果说成已经验证，不从组件名或依赖包名猜测视觉风格。

## 实现契约

1. 保留已有材料收集、缓存和按组件寻址，新增 `src/analyzers/component-design-structure.ts` 提取真实结构、`component-design-description.ts` 分析样式和生成描述，及对应测试。使用现有 Babel/Vue 语法解析结构；显式声明当前锁文件已有的 PostCSS 版本作为直接依赖，用其解析 CSS。无需网络、模型调用或源项目启动。
2. `buildComponentDesignDescription(component, {materials, scenario})` 返回 `{prompt, unresolved}`。`materials` 为本轮内存的 `{filePath,text}` 数组。只将能与组件静态结构关联的样式转为事实；条件选择器保留触发条件，无关选择器不能混入。不能证明的动态样式/复杂效果进入待核对项。
3. 输出面向产品，固定布局、视觉、动效、交互四项：用“弹性布局、间距、圆角、描边、投影、半透明、背景模糊、悬停位移、过渡时长/缓动”等专业中文表达真实声明，不包含源码围栏、文件清单、JSON 或库接入说明。没有足够效果依据时明确说明，不用同一套漂亮话替代每个组件。
4. `component-prompts` 记录升为 `schemaVersion: "0.2.0"`，字段仍为 `componentName/filePath/sourceDigest/sourceFiles/unresolved/prompt`。`sourceFiles` 改为分析所依据的文本文件列表；正文不再嵌入这些文件。旧版记录明确要求重炼，不能作为新版效果描述返回。
5. `sourceDigest` 必须覆盖按路径排序的全部真实材料字节摘要、场景、运行上下文、生成协议与最终描述；即使某个 CSS 声明暂不能翻译，变更仍要让预览失效。保留二进制附件证据在摘要及结构化缺项中。
6. Web 两个入口改为“效果描述提示词”，复制的只有效果需求正文；依据与待核对内容分开展示。MCP `get_component_prompt` 和路径 API 保留，更新描述、版本与测试。清理旧源码模板、围栏函数和过时断言。

## 验证

- 不同 React/Vue 组件产生不同且与真实结构/样式对应的中文效果描述；覆盖尺寸、布局、圆角、阴影、悬停、过渡和有明确依据的关键帧。
- 无关页面/兄弟选择器不得污染描述；复杂动态表达不推断出不存在的交互效果；缺乏样式时不凭名称猜材质。
- 正文不含源码/工程元数据，旧记录不能伪装为效果提示词；复制、MCP 与磁盘保持一致。
- 修改已翻译样式、未翻译样式或二进制字节仍改变材料摘要和预览动作；缓存和速度回归继续通过。
- 最终执行 `node scripts/verify-mvp.mjs`（含构建、全测、CLI 和 MCP）、组件基准脚本及 `git diff --check`；输出一个实际生成的新提示词示例。
- 基准共享样式包含真实悬停上移、220ms 缓出过渡与键盘焦点外轮廓，生成 `output/component-distillation/component-effect-prompt.md`，用于直接检查专业描述；替换上一轮源码版演示产物。

## 当前边界

不新增截图上传或浏览器视觉理解流程。本批不能替代实机观测，也不能准确推断任意脚本驱动的复杂动效；这些缺项应可见。保留静态快速通道，后续实机采集负责补充真实视觉与交互证据。
